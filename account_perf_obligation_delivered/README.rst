This module adds a recognition method for performance obligations whose
revenue (or expense) cannot be spread linearly between two dates,
typically products invoiced on consumption.

With the *Delivered Amount + Projected Balance* method:

- a **delivered amount** (lower than or equal to the total amount) is
  recognized as soon as it is known, without being spread;
- the remaining balance is only **projected** with draft entries, spread
  until the end date, and is never posted until it becomes delivered
  amount;
- the start date is not required, the end date is.

Usage
=====

Select *Delivered Amount + Projected Balance* as recognition method on a
performance obligation, set the end date and update the delivered amount
as the services are delivered.

When recognition entries are posted (menu *Post Recognition Moves* or
the action on the obligations), for each such obligation:

1. the draft projections are deleted;
2. an entry recognizing the delivered amount is created at the posting
   date;
3. the obligation is locked up to the posting date;
4. the remaining balance is projected again from the day after the lock
   date to the end date.

The recognition method can also be set on the product (*Recognition
Method*), and is then copied on the performance obligations created
automatically.
