This module adds a *Not in Service* flag to performance obligations that
already have a recognition period (start and end dates).

Nothing is recognized for an obligation while it is marked as *Not in
Service*. When a recognition posting run reaches an open obligation that
is not in service and whose start date is on or before the posting date,
its start date is moved to the first day of the month following the
posting date and its schedule is regenerated if needed. Directly posting
a recognition entry for an obligation that is not in service is also
blocked.

If postponing the start date would place it after the end date, posting
is blocked with an error unless the dates are adjusted or the obligation
is put in service. When the start date equals the end date, both dates
are postponed; otherwise the end date is kept.

Usage
=====

1. Create or open a performance obligation with a recognition period
   (start and end dates).
2. Check *Not in Service* while the service has not started yet (you can
   also filter obligations using the *Not in Service* search filter).
3. When running recognition posting up to a given date, obligations
   still marked as *Not in Service* with a start date on or before that
   date are skipped for posting; their start date is moved to the first
   day of the following month and their schedule is regenerated.
   Attempting to manually post a recognition entry for an obligation not
   in service raises an error.
4. Uncheck *Not in Service* once the service actually starts so normal
   recognition entries can be posted.
